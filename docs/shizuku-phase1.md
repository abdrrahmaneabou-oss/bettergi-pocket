# Phase 1 — optional Shizuku input

Routes, navigation tolerances, camera gain, movement modes, target approach and collection logic are unchanged. The original TouchClient remains the default. The overlay switch persists the preference and requests permission through Shizuku; the status shows whether the input service proxy is available, not whether the game accepted an action. A route batch pins its selected backend for cleanup. Toggling during a batch stops it; restart explicitly to use the new backend. Loss of Shizuku stops the current batch; fallback on a subsequent start is allowed only when no unresolved Shizuku touch remains. Reconnect/retry attempts a confirmed cancel if necessary.

The new input client serializes native MotionEvents on a bounded worker queue, reuses free pointer IDs, and holds movement across additional taps. It reports submission separately from asynchronous failure, and requires cancellation acknowledgement at cleanup. It does not modify game files. Device validation required: hold for 60 seconds, 100 taps while holding, drag while holding, simultaneous third pointer, pinch, route stop, binder death/reconnect, overlay pass-through, exact 60 ms approach, and comparison on the same route. No claim of measured collection improvement is made.
